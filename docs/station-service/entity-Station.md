> Type: JPA entity → database table `stations`

## What this class is

One `Station` object = one row in the `stations` table. Hibernate reads the annotations and
generates/validates the schema; Jackson reads the getters and turns the object into JSON for
the HTTP response. It is deliberately a **plain data class** (no business logic).

## Generated table

```sql
create table stations (
    id          bigint generated by default as identity,
    city        varchar(255) not null,
    governorate varchar(255) not null,
    name        varchar(255) not null,
    primary key (id)
);
```

(Column order may differ; Hibernate sorts alphabetically in some versions.)

## JSON representation

```json
{
  "id": 2,
  "name": "Station Sousse",
  "city": "Sousse",
  "governorate": "Sousse"
}
```

Every getter becomes a JSON property. `id` is present in responses; on POST the controller
overwrites any client-supplied id with `null`.

## Design notes and limits

- **No validation annotations** (`@NotBlank`, `@Size`) and the controller does not use
  `@Valid`. A JSON body with `"name": null` reaches the database and fails with a 500
  instead of a friendly 400.
- **No unique constraint** on `name`. Nothing prevents duplicate stations.
- **No timestamps** (`createdAt`). If you want an audit trail, add a `LocalDateTime` field.
- **No relationships.** A station does not know its trips — trip data lives in another
  service/database. Cross-service references are plain ids (`trip.departureStationId`).
- **No `equals`/`hashCode`/`toString`.** Lombok offers `@EqualsAndHashCode`/`@ToString` if
  you need to use entities in sets or logs. Careful with `@Data` on entities: it generates
  `equals` over all fields including the id, which is risky with JPA proxies.
